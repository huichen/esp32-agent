# esp32-agent

**Русский** · [English](README.md) · [简体中文](README.zh.md) · [Français](README.fr.md) · [Español](README.es.md) · [العربية](README.ar.md)

Прошивка для ESP32, которая выполняет собственный цикл агента и отдаёт эндпоинт MCP, так что
одна модель может управлять платой напрямую, а любой внешний агент — пользоваться теми же
инструментами по HTTP.

Плату прошивают, она подключается к WiFi и опрашивает шины, для которых есть драйверы. Каждое
ответившее устройство становится инструментами MCP. Агент на плате видит те же инструменты и
отвечает ими; новый датчик можно объявить в JSON, пока плата работает.

> Цикл агента следует [FutureOS](https://github.com/futuregene/future-os): транскрипт, журнал
> вызовов инструментов, события потока, адаптеры протоколов, индекс памяти.

| Что | В подробностях |
|---|---|
| Модель работает на плате | Цикл, инструменты, память и транскрипт — это прошивка; модель — любой эндпоинт, совместимый с OpenAI, или Anthropic. [Как задать модель](docs/model.md) |
| Набор инструментов — это документ | `manifest` (`command: apply`) проверяет манифест JSON и компилирует его в инструменты, действующие уже в том же ходу. [Манифест](docs/manifest.md) |
| Сама находит своё железо | I2C, 1-Wire и объявленные выводы опрашиваются при загрузке; инструменты получает только то, что отвечает. [Возможности](docs/capabilities.md) |
| Один набор инструментов, два вызывающих | Эндпоинт MCP и агент на плате видят одни и те же инструменты из одного описания. [HTTP и MCP API](docs/http-api.md) |
| Консоль по HTTPS | С телефона — чат с моделью и настройка устройств, инструментов, расписания, журналов, WiFi и модели; сертификат плата выпускает сама. [Веб-консоль](docs/web-console.md) |
| Работает без присмотра | Задания по времени и правила по датчикам, которые запускают задание, когда показание пересекает порог. [Работа по расписанию](docs/scheduling.md) |
| Shell и язык скриптов | `shell` с 57 командами с именами из NuttX и интерпретатор для циклов по вызовам инструментов. [Shell](docs/shell.md) · [Script](docs/scripting.md) |

| Приходит со навыками | Три процедуры в прошивке — написать навык, снять распиновку, вернуть к жизни плату, которая выглядит сломанной — появляются в `/skills` при первом запуске; правка остаётся вашей. [Skills](docs/agent-skills.md) |
| Сервер — сама плата | HTTPS с платы, сертификат, который она генерирует, один PIN на три вида вызывающих. [Аутентификация](docs/security.md) |

## Прошить и подключить

```bash
espflash write-bin --chip esp32s3 --flash-size 16mb 0x0 esp32-agent-vX.Y.Z.bin
```

У платы нет данных WiFi, поэтому она поднимает точку доступа `esp32-agent-setup`.
Подключитесь, откройте `http://192.168.4.1/`, введите имя сети и пароль, сохраните. Они
уходят в NVS, плата переподключается. До этого она не достанет ничего вне локальной сети:
ни эндпоинт модели, ни зеркало пакетов.

## Использование

**В браузере**: `http://<board>/` (или `https://<board>/`) — это консоль. Поговорить с
моделью, посмотреть найденные устройства, включить или выключить инструменты, прочитать
журнал, задать PIN.

**Из агента**: `GET http://<board>/agent.json` отдаёт интерфейс в JSON — каждый маршрут с
методом, телом и авторизацией, поверхность MCP, таблицу настроек с типами и значениями по
умолчанию, и пределы. Агенту, умеющему запросить URL, больше ничего не нужно.

**Новая плата уже знает три вещи.** `/skills/create-skill` — как агент пишет следующую процедуру, `/skills/pinout` — как снять распиновку и записать её в `/MEMORY.md`, `/skills/recover-board` — что делать, когда плата выглядит сломанной. Это обычные файлы рабочей области: при первом запуске ставятся там, где путь пуст; сброс к заводским вернёт их, а `skills.seed_defaults=false` это отменит. Первая полезная фраза только что прошитой плате — «запиши свою распиновку».

## Дайте ей модель

Откройте `http://<board>/`, панель **Agent**, укажите адрес, идентификатор модели и ключ,
сохраните. Ключ только на запись: уходит в NVS и читается как `__set__`. На той же панели —
`protocol` (`chat`, `responses` или `anthropic`), `reasoning`, `context_tokens` и
`max_output_tokens`.

**Или поручите это агенту.** Получив `agent.json`, агент знает эти настройки, их типы и
значения по умолчанию, поэтому достаточно одной фразы:

> направь плату на `https://your-provider/v1/chat/completions`, модель `…`, ключ `sk-…`,
> рассуждения `low`, контекст `64000`, вывод `4096`

Агент применит их через `POST /api/agent/config` — тем же вызовом, что и панель, — и перечитает
конфигурацию для подтверждения. Командная строка вам не нужна, и та же фраза годится для любой
платы, до которой он дотянется. Совсем без ключа `base_url` на
`http://127.0.0.1/selftest/chat/completions` гоняет цикл по самой плате.

## О безопасности

- **Учётные данные остаются на плате.** WiFi пишется в NVS через `provision`, а не в образ;
  `api_key` доступен только на запись и читается как `__set__`.
- **Задайте PIN, прежде чем плата уедет с вашего стола.** `auth.portal_pin` закрывает все
  записи и те чтения, что показывают транскрипт, промпт, конфигурацию и журналы.
- **Сравнивайте сертификат.** Он самоподписанный, отпечаток — в `GET /api/tls`. Порт 80
  открыт по умолчанию: плохой сертификат стоит URL, а не платы; `mcp.plain_http: false`
  закрывает его, и тогда вернуться можно только по USB.
- **`shell`, `script` и инструменты манифеста двигают выводы.** В этом и смысл платы; PIN —
  граница между агентом за работой и прохожим.

[Security](docs/security.md) перечисляет, что намеренно не защищается.

## Состояние

| Часть | Состояние |
|---|---|
| `agent-core` | 735 модульных тестов и 5 интеграционных проходят; `scripts/smoke.ps1` проходит от начала до конца |
| Симулятор | консоль, MCP и цикл агента работают от начала до конца |
| Прошивка | прошита на ESP32-S3-DevKitC-1 N16R8 (IDF v5.5.2): 42 инструмента, OLED 128×32, микрофон и усилитель I²S, WS2812, консоль по TLS, ходы модели по HTTPS |
| Не реализовано | OTA, SD-карта, DHT11/22, камера. См. `ROADMAP.md` |

Цифры на стенде: ход с четырьмя инструментами за 13.7 s; консоль по TLS за 0.55 s; сканирование
I²C стабильно на 8 прогонах; внутренняя SRAM 5–6 kB свободно после страницы по TLS — самое узкое
место здесь.

Новая периферия начинается как фрагмент манифеста в `examples/manifests/`; драйвер на Rust
нужен только для таймингов, калибровки или состояния. `CATALOG` — место, где драйвер
регистрирует себя. Соглашения — в [AGENTS.md](AGENTS.md) и [CONTRIBUTING.md](CONTRIBUTING.md).
