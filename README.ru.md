# esp32-agent

**Русский** · [English](README.md) · [简体中文](README.zh.md) · [Français](README.fr.md) · [Español](README.es.md) · [العربية](README.ar.md)

Прошивка для ESP32, которая выполняет собственный цикл агента и отдаёт эндпоинт MCP, так что
одна модель может управлять платой напрямую, а любой внешний агент — пользоваться теми же
инструментами по HTTP.

Плату прошивают, она подключается к WiFi и опрашивает шины, для которых есть драйверы. Каждое
ответившее устройство становится инструментами MCP. Агент на плате видит те же инструменты и
отвечает ими; новый датчик можно объявить в JSON, пока плата работает.

> Цикл агента следует [FutureOS](https://github.com/futuregene/future-os): транскрипт, журнал
> вызовов инструментов, события потока, адаптеры протоколов, индекс памяти. Там, где прошивка
> отличается (килобайты вместо гигабайт RAM, никаких сводок, написанных моделью), код
> объясняет почему.

| Что | В подробностях |
|---|---|
| Модель работает на плате | Цикл, инструменты, память и транскрипт — это прошивка; модель — любой эндпоинт, совместимый с OpenAI, или Anthropic. [Как задать модель](#как-задать-модель) |
| Набор инструментов — это документ | `manifest_apply` проверяет манифест JSON и компилирует его в инструменты, действующие уже в том же ходу. [Манифест](#манифест) |
| Сама находит своё железо | I2C, 1-Wire и объявленные выводы опрашиваются при загрузке; инструменты получает только то, что отвечает. [Возможности](docs/capabilities.md) |
| Один набор инструментов, два вызывающих | Эндпоинт MCP и агент на плате видят одни и те же инструменты из одного описания. [HTTP и MCP API](docs/http-api.md) |
| Консоль по HTTPS | С телефона — чат с моделью и настройка устройств, инструментов, расписания, журналов, WiFi и модели; сертификат плата выпускает сама. [Веб-консоль](#веб-консоль) |
| Работает без присмотра | Задания по времени и правила по датчикам, которые запускают задание, когда показание пересекает порог. [Работа по расписанию](#работа-по-расписанию) |
| Shell и язык скриптов | `shell` с 26 командами с именами из NuttX и интерпретатор для циклов по вызовам инструментов. [Shell](#shell) · [Script](#script) |
| Помнит, что ей сказали | Постоянные указания, `/AGENTS.md`, индекс `/memory.md` и навыки, собранные в промпт на каждом ходу. [Что модель видит всегда](#что-модель-видит-всегда) |
| Никакого облака на пути | HTTPS с платы, сертификат, который она генерирует, один PIN на три вида вызывающих. [Аутентификация](#аутентификация) |
| Проверяемо без железа | Симулятор запускает тот же `agent-core` на виртуальной плате. [Симулятор](#симулятор) |

## Прошивка и подключение

```bash
cargo install espup espflash ldproxy
espup install
powershell scripts/build-firmware.ps1 -Flash -Port COM3
```

Без сохранённых учётных данных плата поднимает собственную точку доступа. Подключитесь к ней с
телефона и откройте `http://192.168.4.1/`, либо отправьте `provision <ssid> <password>` по USB.
Учётные данные уходят в NVS и никогда в образ.

```bash
curl -sS http://<board>/agent.json | jq '.endpoints | length'
curl -sS -X POST http://<board>/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | jq '.result.tools | length'
curl -k -sS https://<board>/api/tls | jq -r .fingerprint
```

Порт 443 отдаёт те же маршруты по TLS с сертификатом, сгенерированным при первой загрузке;
браузеры предупреждают, поэтому сравните отпечаток. Порт 80 остаётся открытым, так что плохой
сертификат стоит одного URL, а не платы. `GET /agent.json` — весь интерфейс как данные: 40
маршрутов с методом, телом, возвратом и аутентификацией, плюс каждая записываемая настройка с её
типом и значением по умолчанию.

## Веб-консоль

| Где | Что там делают |
|---|---|
| Чат (страница) | разговор с моделью; вызовы инструментов и рассуждения сворачиваются в одну строку на ход |
| Устройства | что нашёл опрос, выводы, адреса, `Probe devices`, кандидаты на подключение |
| Инструменты | каждый инструмент со своей схемой входа и почему один скрыт |
| Агент | эндпоинт, модель, ключ, протокол, уровень обдумывания, температура, размер контекста и вывода |
| Расписание | задания по времени и правила по датчикам |
| Журналы, Настройки | кольцевой буфер; WiFi с переопределением шлюза и DNS, PIN, перезагрузка |

Никакого шага сборки и ничего, загружаемого из интернета: около 58 KB HTML, CSS и JavaScript,
скомпилированных внутрь и отдаваемых с `Cache-Control: no-store`, поэтому перепрошивка видна при
следующей перезагрузке страницы.

## Как задать модель

```bash
curl -sS -X POST http://<board>/api/agent/config -H 'Content-Type: application/json' \
  -d '{"base_url":"https://future-os.cn/api/v1/chat/completions",
       "model":"deepseek-flash","api_key":"<key>"}'
curl -sS -X POST http://<board>/api/agent/message -H 'Content-Type: application/json' \
  -d '{"text":"write HELLO on the OLED, set the LED blue, then scan I2C"}'
```

Три протокола: `chat` (chat completions OpenAI), `responses` (Responses API OpenAI) и
`anthropic` (Messages API). Изображения из консоли уходят как части содержимого. `reasoning`
задаёт уровень обдумывания, `max_steps` ограничивает число обращений к модели на ход (0 = без
ограничения), `context_tokens` и `max_output_tokens` задают окно и резерв под ответ, а транскрипт
сжимается при 80 % окна. Без ключа направьте `base_url` на собственный
`/selftest/chat/completions` платы, и цикл всё равно работает.

## Что модель видит всегда

Четыре слоя входят в системный промпт, в этом порядке, на **каждом** ходу: то, что владелец написал один раз, и то, что агент узнал после. Ничего из этого нет в транскрипте, поэтому это стоит одинаково и для разговора из одного сообщения, и из тысячи.

| Слой | Где живёт | Сколько доходит до модели | Кто пишет |
|---|---|---|---|
| Постоянные указания | `agent.system_prompt` (NVS) | целиком, предел 2 KB | владелец, по HTTP или через `shell` |
| Инструкции проекта | `/AGENTS.md` | первые 1 KB, затем метка о том, что остальное там | владелец, через `fs_write` |
| Долговременная память | `/memory.md`, индекс, указывающий на `/memory/<topic>.md` | только индекс, 24 строки / 2 KB | сам агент, по мере обучения |
| Навыки | `/skills/<name>/SKILL.md` и то, что лежит рядом | по одной строке на каждый: имя и описание | любой из двух |

```bash
# Постоянные указания владельца: зачем эта плата и какие правила идут первыми.
curl -sS -X POST http://<board>/api/agent/prompt -H 'Content-Type: application/json' \
  -d '{"action":"set","text":"Реле насоса на GPIO12. Никогда не гонять дольше двух минут."}'

# Что модель получит на самом деле, со всеми слоями — единственный способ это проверить.
curl -sS http://<board>/api/agent/prompt | jq -r .system
```

`action` принимает `set`, `append` или `clear`; `system_prompt get` читает его обратно с платы, а
`system_prompt set …` записывает со стороны агента. Память и навыки — обычные файлы:
`fs_write /memory/wiring.md "GPIO18 = светодиодная лента"` плюс одна строка в `/memory.md` — это вся
память, а удаление файла забывает её. Изменённый файл вступает в силу на следующем ходу: без
перезапуска, без перепрошивки, без перезаписи транскрипта.

Размеры — причина такого разделения. Плата с килобайтами внутренней SRAM не может позволить себе
нести всё, что знает, в каждом запросе, поэтому каждый слой — индекс или префикс, а дорогая часть
подтягивается через `fs_read`, когда она действительно нужна на ходу.
[docs/agent-memory.md](docs/agent-memory.md) и [docs/agent-skills.md](docs/agent-skills.md)
содержат детали, включая то, как ограничен индекс.

## Shell

Каждый драйвер в каталоге документирован в [docs/capabilities.md](docs/capabilities.md): GPIO,
ADC, PWM, I2C, 1-Wire, WS2812, SSD1306, BME280, SHT3x, INA219/226, MPU6050, ADS1115, PCF8574,
DS18B20, HC-SR04, сервопривод, реле, микрофон и усилитель I²S.

Одна записываемая область, 8 KB текста в NVS. `read`, `write` и `edit` покрывают обычные случаи;
всё остальное — одна командная строка `shell`, разбираемая на слова, кавычки и `--flags`.
Результат инструмента ограничен 2 KB, ответ — 8 KB: у платы 8 MB PSRAM и несколько килобайт
внутренней SRAM, и связывает именно второе число:

```text
shell {"command":"ls /notes"}            shell {"command":"grep GPIO /"}
shell {"command":"cp /a.txt /b.txt"}     shell {"command":"rm /a.txt --confirm"}
shell {"command":"curl https://example.com/"}          # GET, HTML reduced to text
shell {"command":"wget -o /dl/page.txt https://example.com/"}
shell {"command":"ping -c 3 192.168.3.1"}   shell {"command":"nslookup example.com"}
shell {"command":"ifconfig"}                # configured gateway and DNS, not the lease
shell {"command":"df | free | uptime | date | uname | ps"}
shell {"command":"sha256sum /notes/a.txt"}  shell {"command":"zip t.zip /a.txt"}
```

`edit` отказывается от неоднозначного совпадения, а не переписывает не то место; `rm` и `mv`
требуют `confirm`. Неверная команда отвечает своей строкой использования, взятой из той же
таблицы, из которой берётся текст справки, поэтому они не могут разойтись: `rm` без `--confirm`
возвращает `usage: rm <path> --confirm`. `shell {"command":"help"}` перечисляет все 26.

## Script

Для того, что фиксированные инструменты выразить не могут: цикл по показаниям, ветвление по
результату.

```text
let scan = tool("i2c_scan", {})
let i = 0
while i < len(scan.addresses) { log(scan.addresses[i])  i = i + 1 }
if i > 0 { "found " + str(i) } else { "nothing" }
```

Числа, строки, логические значения, nil, списки, словари; `let`, присваивание, `if`/`else`,
`while`, `break`; встроенные `len`, `str`, `num`, `type`, `log` и `tool(name, args)`, который
вызывает любой инструмент платы с правами самого вызывающего (кроме `tool("script")`).
`{"lint":true}` проверяет синтаксис и неизвестные имена с указанием строки и столбца и ничего не
выполняет; `{"help":true}` возвращает справку. Границы: 30 s, пять миллионов шагов, 32 вложенных
блока, строки 4 KB, 8 KB исходника. Реальная граница — часы: интерпретатор работает в потоке,
который обслуживает консоль.

## Работа по расписанию

```bash
curl -sS -X POST http://<board>/api/sched -H 'Content-Type: application/json' -d '{
  "tasks":[{"id":"t1","prompt":"read the BME280","every_s":300}],
  "rules":[{"id":"r1","tool":"bme280_read","path":"temperature_c","op":"gt","value":30,"prompt":"it is hot"}]}'
```

`at_hhmm` вместо этого запускает задание в указанное время по UTC, и каждый ответ попадает в транскрипт с
меткой `source: "schedule:t1"`. Агент может планировать себя сам через
`schedule {"action":"add", …}`. Задания переживают перезагрузку.

## Манифест

Устройство, которому не нужны тайминги и калибровка, объявляется, а не компилируется:

```json
{"devices":[{"id":"pump","kind":"actuator","pins":{"out":12},"note":"active-low relay"}],
 "tools":[{"name":"pump_pulse","description":"Energise the relay for `ms` ms",
   "params":[{"name":"ms","type":"integer","min":10,"max":5000,"required":true}],
   "exec":{"type":"sequence","steps":[
     {"ms":0,"exec":{"type":"gpio_write","pin":12,"level":0}},
     {"ms":0,"exec":{"type":"delay","ms":{"param":"ms"}}},
     {"ms":0,"exec":{"type":"gpio_write","pin":12,"level":1}}]},
   "safety":{"max_calls_per_min":20,"confirm":true}}]}
```

Три пути добавляют железо: манифест (без таймингов и конечного автомата, применяется на ходу),
скомпилированный драйвер (`drivers/<chip>.rs`, для конечных автоматов и жёстких таймингов) или
профиль платы (факты, которые нельзя опросить, например какие выводы используют светодиод и
кнопки). Драйвер попадает в список, только когда опрос нашёл устройство, поэтому наполовину
написанный драйвер не может отрапортовать о железе, которого нет. Проверка идёт на плате:
диапазоны параметров и предел `safety` на минуту проверяются до того, как двинется вывод, а вызов
вне диапазона возвращает диапазон, который он принял бы.
[docs/adding-a-device.md](docs/adding-a-device.md) описывает все три.

## Аутентификация

| Вызывающий | Учётные данные |
|---|---|
| Консоль | `POST /api/auth {"pin":"…"}` возвращает bearer-токен, который хранит страница |
| Script | `X-Portal-Pin: <pin>`, или тот же токен |
| Клиент MCP | `Authorization: Bearer <mcp.token>`; PIN принимается, когда токен не задан |

Если задан `auth.portal_pin`, он нужен для записей и для чтений, раскрывающих транскрипт,
промпт, конфигурацию и журналы; состояние, устройства, инструменты и `/agent.json` остаются
открытыми. Токены живут в RAM, поэтому перезагрузка их отзывает. По умолчанию PIN не задан, и
`/agent.json` говорит об этом в своём блоке `security`.

## Симулятор

```bash
cargo run -p esp32-agent-sim
```

Тот же `agent-core` на виртуальной плате на реальном порту. Отличается только реализация
`Hardware`, поэтому консоль, эндпоинт MCP, драйверы, движок манифестов и цикл агента — это код,
который работает на чипе.

## Структура репозитория

`crates/` собирается и тестируется на хосте; `firmware/` — бэкенд ESP-IDF. `agent-core` — это
плата за одним трейтом `Hardware`, без кода под конкретный чип, поэтому `cargo test` гоняет его
на ноутбуке; `agent-sim` реализует этот трейт поверх файла регистров. Их слияние вложило бы
симулятор в каждый образ, а зависимости прошивки — в каждый тест. `firmware/` исключён из
workspace, потому что ему нужны `cargo +esp`, `-Zbuild-std` и выкачанный ESP-IDF.

```
crates/agent-core/    hardware.rs (the trait) · drivers/ (one module per chip) · boards.rs ·
                      manifest.rs · agent.rs + llm.rs · sched.rs · tools/ ·
                      http.rs · app.rs · sitemap.rs + settings.rs · virtual_board.rs
crates/agent-sim/     the virtual board behind an HTTP port
firmware/             main.rs (boot order) · runner.rs (agent thread, TLS) ·
                      esp_hw.rs (GPIO/I2C/PWM/ADC/RMT/I2S) · console.rs · wifi.rs
```

## Состояние

| Часть | Состояние |
|---|---|
| `agent-core` | 427 модульных тестов и 14 интеграционных проходят; `scripts/smoke.ps1` проходит от начала до конца |
| Симулятор | консоль, MCP и цикл агента работают от начала до конца |
| Прошивка | прошита на ESP32-S3-DevKitC-1 N16R8 (IDF v5.5.2): 42 инструмента, OLED 128×32, микрофон и усилитель I²S, WS2812, консоль по TLS, ходы модели по HTTPS |
| Не реализовано | OTA, SD-карта, DHT11/22, камера. См. `ROADMAP.md` |

Цифры на стенде: ход с четырьмя инструментами за 13.7 s; консоль по TLS за 0.55 s; сканирование
I²C стабильно на 8 прогонах; внутренняя SRAM 5–6 kB свободно после страницы по TLS — самое узкое
место здесь.
