# Project audit — November 2026

## Outcome and scope

The audit covers protocol/HTTP framing, internal and external tool dispatch, model
adapters, memory admission, persistence, file formats, scripts/scheduling, media
framing, the portal, build wrappers and documentation. Confirmed regressions were
fixed and given repeatable tests. This is not a claim that every bug, driver,
provider or hardware operating condition has been exhausted.

Evidence was collected on Windows on 2026-11-13:

- Runtime source and full ordered repository gate: `6e78043`.
- Expanded live interface harness and its full run: `72b2819` (a test-only change;
  runtime source is unchanged from `6e78043`).
- Core: **831 unit tests + 5 integration tests passed**, none ignored. The integration
  tests include actual headless Chromium rendering of the shipped portal at phone widths.
- Live interfaces: **1,089 checks passed, 0 failed**, across 14 areas, in **37.645 s**.
  That duration is the host harness's elapsed time, not board throughput or model latency.
- All **19 initially advertised default-board tools** succeeded over external MCP and
  through the internal agent in **each** of Chat, Responses and Anthropic. Each internal
  result was compared with the actual follow-up model request, including file/save effects.
- Offline firmware-wrapper regressions: **22 passed** across Bash and PowerShell.
  Both tracked `.sh` files also passed `bash -n`.
- Eight README languages passed the offline parity/link guard and its **14 rejected
  mutation fixtures**. Japanese and Korean were added; native-speaker review remains open.
- The ESP32-S3 release firmware compiled and linked independently. It was **not flashed
  or board-tested**. Build evidence and warning counts are below.

Documentation-only publication commits can follow these evidence revisions without
changing the audited runtime. The machine-generated interface report includes the
source revision, simulator/harness checksums, every assertion, coverage and explicit gaps.

The detailed contracts and tests, rather than this table, define the behavior. In
particular, a refused **admission** is different from a later asynchronous backend
refusal, and an incomplete streamed upload may already have played earlier samples.

## Performance and memory assessment

### Improvements made without claiming unmeasured speedups

- HTTP parsing no longer needs the former redundant full-body copies. Bounded headers
  and an incrementally decoded body replace full response accumulation and reslicing.
- Store range/stream readers copy requested slices and reuse the caller's buffer
  (up to 8 KiB per pull), rather than adding the former extra 64 KiB buffer.
  A backend using the default `read_at` can still materialize a value.
- Saved JSONL, workspace parsing, inflate and ZIP admission enforce their respective
  budgets **before** large output growth/copies. The ZIP writer borrows names and
  makes a fallible exact output reservation after admission.
- Replacing a queued workspace generation shares unchanged pending text buffers rather
  than cloning them again. Incremental publication does not rewrite every unchanged file.
- Periodic flash drains run outside the global App mutex. Model network latency is also
  outside that mutex; the live slow-model case checks portal responsiveness. Queue/backend
  locks can still block a caller holding the App mutex, and reboot's final drain is special.
- Tool descriptions and the generated model instructions now use current limits. Compact
  help/pipeline/archive policies are identified as local policies, not invented SRAM limits.

These are allocation/ordering changes established by source and regression behavior.
There is no new board speed, power, fragmentation or peak-heap benchmark in this audit.
Historical bench readings remain labelled historical in [troubleshooting](troubleshooting.md).

### Budgets are not simultaneously available capacity

| Resource | Current policy | Important distinction |
|---|---|---|
| Nominal PSRAM | 8 MiB | Also holds active objects, allocator overhead, request/TLS/media buffers and some task allocations |
| Retained history | 2 MiB payload / 1,024 messages | Token compaction usually acts earlier; the newest-message exception is documented, not an absolute allocator bound |
| User / assistant text | 32 KiB each | Oversized input is refused; clipped output adds a truncation marker outside its prefix budget |
| Agent tool text | 64 KiB prefix | Clipped output can add a marker; the network tool separately budgets its complete JSON result |
| Saved transcript | 512 KiB encoded JSONL | Newest complete exchanges/pairs; no attachment payloads; not the full RAM history |
| RAM workspace | 256 KiB/file, 4 MiB text, 1,024 files | Plus string/map capacities, saved hashes and rollback/request copies |
| Workspace paths | 256 bytes canonical/path, 128 KiB aggregate names | Raw paths also have a 1,024-byte pre-normalization bound |
| Pending store queue | 6 MiB charged bytes, 2,304 key/metadata slots | Admission policy includes value/key/operation/publication charges; neither free heap nor completed flash |
| Pipeline / inline ZIP | 8 KiB stdout / 1,400-byte archive before base64 | Independent compact policies, not the global tool-text or workspace budget |

One extra copy of a 2 MiB history consumes another 2 MiB; JSON escaping can expand
one control byte to six encoded bytes. The workspace, saved-hash/rollback maps,
queued values, model request and media can coexist. Adding all configured maxima is
not a feasible 8 MiB heap plan. The workspace change guard uses twice its estimated
allocated RAM plus 64 KiB free PSRAM; small metadata allocations and other paths still
use ordinary Rust allocation. Fragmentation and serialization peak remain board checks.

Internal SRAM remains important for cache-disabled flash work, task stacks and DMA
metadata. Free PSRAM does not repair an internal contiguous-block shortage. The
firmware writer retains its internal-RAM stack; this release build does not measure
its runtime behavior.

### Media limits are still separate work

Current calls are **1 s maximum microphone WAV** (default 256 samples), **12 s score
playback**, **30 s per HTTP PCM/AV upload**, and a **160×120 luma thumbnail**. Score
playback still synthesizes the whole mono clip and writes 4,096-sample pieces; chunked
writes alone do not make synthesis bounded-memory or the call asynchronous.

The firmware DVP capture path remains unsupported. No JPEG download route, verified
1080p camera, long mic-to-file recording, background 60 s score playback, onboard
Opus/ADPCM encoder or SD FAT filesystem was added. Larger media belongs in streaming/
file routes with jobs and cancellation, not base64 in the conversation or a larger
single buffer. See [audio](audio.md) and the [roadmap](../ROADMAP.md).

## File formats and durability

The source partition table has four entries, no OTA slots: `nvs` at `0x9000/0x6000`,
`phy_init` at `0xf000/0x1000`, `factory` at `0x10000/0x400000`, and `storage` at
`0x410000/0xbf0000`. Storage is **12,517,376 bytes = 11.9375 MiB**. Its CSV subtype
is `spiffs`; the mounted runtime component is **LittleFS 1.23.1**. The old SPIFFS
format/capacity observations are not LittleFS measurements.

- Configuration/secrets remain in NVS. Dependency source establishes preservation of
  the preceding string on a no-space refusal when set without erase-first; this is not
  a new board measurement. Arbitrary flash/commit errors are not promised to roll back
  every change.
- Workspace persistence uses a plain path-to-key JSON index and per-file values with
  short, path-derived physical keys. The bounded document shape is
  `{"version":1,"files":{"/path":"text"}}`; legacy `ws1` chunks remain readable for migration.
- A successful file tool reports RAM edit and **queue admission**, with `queued: true`,
  `saved: false` and a persistence note. Completed generation receipts advance saved
  hashes. Backend failure leaves the RAM edit and observable diagnostics; it does not
  become a synchronous rollback or durable success.
- Required values precede the index; cleanup follows successful dependencies/index.
  Existing path-addressed values may already have changed before another value/index
  fails. This is **not an all-files transaction** or a power-cut durability proof.
- LittleFS replacement syncs a temporary file before rename. Published values win over
  old backups during recovery. A failed replacement needs enough space for old and
  temporary values simultaneously. The mount policy **still permits formatting a volume
  that fails to mount**, not only an empty volume; nondestructive recovery is still open.
- Stored/deflated ZIP32 is supported within 3,072 payload bytes, 3,072 name bytes and
  128 entries; the writer emits stored entries. ZIP64, encryption, arbitrary binary
  workspace files and a general compressed-file transport are not implemented.
- PCM is signed 16-bit little-endian mono at 24 kHz; the custom tagged `av1` upload
  is defined in [audio](audio.md), not an AOM AV1 video codec.

[Storage](storage.md) spells out parser bounds, queue/publication ordering, recovery
and acknowledgement limits. A filesystem partition increases persistent storage,
not the RAM available to the workspace or the model request.

## Reproduction and build evidence

Run the repository gate in order (use `bash scripts/smoke.sh` on a Unix host):

```text
cargo test -p esp32-agent-core
cargo build -p esp32-agent-sim
powershell -NoProfile -File scripts/smoke.ps1
cargo clippy -p esp32-agent-core -p esp32-agent-sim -- -D warnings
cargo fmt --all --check
```

Then run the expanded host checks:

```text
python scripts/test-interfaces.py --report target/interfaces.json
python scripts/test-build-firmware.py
python scripts/check-readmes.py --self-test
bash -n scripts/build-firmware.sh
bash -n scripts/smoke.sh
cargo fmt --manifest-path firmware/Cargo.toml -- --check
```

The interface suite starts isolated loopback processes/state, injects deterministic
responses/failures, exits nonzero on failure and records gaps. It has a 240 s overall
budget with bounded cleanup. Browser integration needs Chromium/Chrome/Edge; the offline
wrapper suite reports missing shells as skipped. No skip occurred in this evidence run.

Host toolchain: Rust/Cargo **1.99.1**, Python **3.13.16**. Firmware toolchain:
`esp` Rust **1.97.0-nightly**, ESP-IDF **5.5.2**, ESP32-S3 N16R8 target.
The independent Windows release build used `scripts/build-firmware.ps1` with a short
output directory and **without `-Flash`**, against runtime revision `6e78043`:

## Prioritized remaining work

1. **Board persistence and heap stress:** LittleFS ENOSPC, same-key read/replace/remove,
   legacy backup recovery and controlled interrupted writes; simultaneously exercise
   history/workspace/queue/TLS/media while measuring internal and PSRAM largest blocks,
   high-water allocation and task stacks. Do not turn a selected limit into a measured one.
2. **Nondestructive mount recovery:** distinguish fresh volume/explicit migration from
   unreadable existing data, and make destructive formatting an explicit recovery action.
3. **Reduce locked/duplicated work:** long shell network/wait and hardware/media calls
   still hold the App mutex. Add bounded background jobs/cancellation; consider touched-file
   undo or copy-on-write workspace edits and streaming model serialization after profiling.
4. **Binary media transport:** implement long recording/file downloads and bounded-memory
   background playback; implement and board-verify camera acquisition/JPEG before 1080p claims.
5. **Broaden automation:** run the durable host suite in CI and on Unix; add per-driver
   simulator cases and shell parameter matrices. Real daily-time/SNTP/radio, TLS/provider
   compatibility, session TTL expiry and full SSE heartbeat/120 s lifetime still need evidence.
6. **Documentation/tool maintenance:** keep executable discovery, schema and docs tied to
   constants; native-review Japanese/Korean; reconcile firmware warning configuration without
   globally hiding useful warnings. OTA still needs a new partition/update/rollback design.
